Proposed Architecture — LLM as Post-Processing Layer

Data Fetchers → Technical Analysis → Rule-Based Scoring → LLM Synthesis → Reports & Alerts

The LLM sits after computation, not inside it. All technical indicators, scores, and data remain deterministic. The LLM adds narrative synthesis, cross-module intelligence, and context-aware interpretation.

Where NOT to Use LLMs

  • Technical indicator computation — RSI, ATR, Bollinger, etc. are faster and correct in NumPy
  • Data fetching / parsing — your scraper logic is already robust with retries, caching, fallbacks
  • Hard gate logic in breakout_v5 — deterministic gates are backtestable; LLMs introduce non-reproducibility
  • Score computation — weighted linear scoring is transparent and tunable; an LLM black box is worse
  • Anything real-time — LLM latency (1-5s) is fine for daily analysis but not intraday scanning
